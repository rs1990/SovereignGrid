Distributed inference

Your GPU, someone else's workload, nobody's data center.

SovereignGrid pools the idle GPUs of a guild of developers into a single asynchronous inference API. Providers run a daemon that binds to their local Ollama or vLLM engine and authenticates with a wallet signature. A FastAPI orchestrator dispatches consumer requests to the least-loaded node and prices each completion into an append-only compute-credit ledger.

What it does

Guild membership is the trust boundary.

A provider daemon opens a persistent WebSocket to the gateway. The gateway answers with a one-time nonce; the daemon signs grid-auth:<nonce> with its wallet key using EIP-191 and returns its active models and concurrency limit. The recovered address must appear in guild_members with a valid Guild Administrator signature over guild-admit:<wallet>, re-verified on every connect. A spoofed row without that admin signature is rejected. The private key never leaves the provider machine.

Consumer requests hit an OpenAI-shaped endpoint, pass through a regex sanitization sandbox that rejects shell-injection and reverse-shell payloads before any provider sees them, and are matched to the least-loaded online node serving the requested model. Every node runs at most max_concurrency jobs at once.

Failure handling converges. A WebSocket disconnect requeues every in-flight job on that socket immediately. A dispatch timeout requeues. An APScheduler sweep every 15 seconds catches any running job whose lease expired through a missed disconnect or a network partition. After three attempts a job is marked dead rather than looping forever.

Each completed inference appends one ledger row priced by model size, so a 70B model pays roughly 6.7 times an 8B per generated token. Node balances update only in an hourly settle_ledger() batch, one short transaction per hour instead of a write lock per inference.

Engineering details

The decisions that carry the design.

01

Wallet-native auth without a blockchain

EIP-191 signatures replace passwords, and a Supabase table serves as the guild registry. No smart contracts are involved. Guild admins grant and revoke membership by signing offline.

02

BYOK provider daemon

Only the wallet address and a signature cross the wire. Nonces are consumed on use with a 60 second TTL, so a captured handshake cannot be replayed.

03

Smart dispatch

A live registry keeps a model-to-nodes index and picks the node with the fewest active jobs, tracking concurrency per connection rather than per machine guess.

04

Three-layer failover

Disconnect, dispatch timeout, and expired lease all converge on the same requeue path, so consumers fail over across nodes transparently and no failure mode needs its own recovery code.

05

Sanitization sandbox

Ten denylist patterns block pipe-to-shell, fork bombs, reverse shells, file:///etc paths, and dangerous system calls before a payload reaches a provider machine. Heuristic by design; guild trust remains the primary boundary.

06

Atomic settlement in PL/pgSQL

settle_ledger() aggregates unsettled rows per node, updates balances, and flips the settled flag in a single transaction, keeping the inference hot path free of write contention.

07

Dual-mode store

MemoryStore runs the whole grid with no database for development and demos. Setting SUPABASE_URL swaps in the Postgres-backed store behind the same interface.

08

Model-size-aware crediting

A prefix-pattern rate table prices output tokens by parameter count: 10 credits per 1k tokens for 70B, 1.5 for 8B, 1.2 for 7B, 0.8 for 4B.

Numbers from the code

Measured or configured values, not projections.

  • Consumer max_tokens: 1 to 32,768, default 1,024
  • Provider max_concurrency: 1 to 64 per node
  • Job lease TTL: 300 seconds, configurable
  • Job max attempts: 3 before a job is marked dead
  • Requeue sweep interval: 15 seconds
  • Dispatch timeout: 300 seconds
  • Nonce TTL: 60 seconds, fixed
  • Daemon heartbeat: every 30 seconds with active job count
  • Reconnect backoff: 1 second to 60 seconds, exponential
  • Payload size cap: 200,000 characters
  • 6 database tables plus one PL/pgSQL settlement function
  • 10 regex patterns in the sanitization denylist

Status

An honest account of what is built and what is not.

Prototype moving toward MVP, functional end to end: handshake, dispatch, execution, result handling, and settlement all work. Every implemented endpoint is complete with clean error paths and there are no stubs in the shipped code.

Known scope limits, all documented in the repository README. There is no SSE streaming relay, so whole results are returned. Consumer auth is a hashed bearer key rather than metered billing. Token counts are trusted as reported by the daemon with no cross-check. The orchestrator runs as a single instance with an in-process registry, so horizontal scaling would need sticky routing or a shared dispatch bus.

The gateway runs with no database at all when SUPABASE_URL is unset, which makes local evaluation a two command exercise.
